# Liquid Glass：不是透明底加 blur

Liquid Glass = 材质 + 光学 + 行为。缺任何一项，它只是普通[磨砂](frosted.md)。底座里的 Glassmorphism 风格描述的是“看起来像玻璃”；本篇定义的是“作为一块玻璃如何存在于界面里”。

## 1. 什么时候用

产品身份明确的局部：媒体播放器、Dock 类常驻浮层、沉浸内容上的控制层。它是产品的一部分，不是给任意卡片加的滤镜。表单、表格、告警、确认弹窗等需要绝对可读的信息不用。

## 2. 十一个维度

| 维度 | 定义 | Web 近似实现 | 缺失时的表现 |
|---|---|---|---|
| Material 材质 | 玻璃是有厚度的一层，不是一片透明色 | 承载面 `color-mix` + 内描边表达厚度 | 看起来像半透明矩形 |
| Blur 模糊 | 下层内容失焦，但仍能感知色彩与运动 | `backdrop-filter: blur(16–24px) saturate(1.2–1.4)` | 下层文字穿透，可读性崩 |
| Refraction 折射 | 边缘处下层内容轻微位移 / 弯折 | 边缘渐变蒙版 + 轻微 `backdrop-filter` 差异；不做也可接受 | 边缘生硬，像贴纸 |
| Transparency 透明度 | 透出多少下层，取决于承载的信息密度 | 控制层 70–85% 底色；纯装饰层可更透 | 密度错配：正文透、装饰实 |
| Specular Highlight 高光 | 顶部受光边有一条细亮线 | `inset 0 1px 0 rgb(255 255 255 / .35)` | 没有“体积” |
| Edge Light 边缘光 | 底部 / 背光边有一条细暗缘，与高光成对 | `inset 0 -1px 0 rgb(0 0 0 / .12)` | 只有亮边像描边 |
| Depth 深度 | 玻璃层与实色层有明确覆盖关系 | 一层外阴影 `--ui-shadow-lg`；玻璃上不叠玻璃 | 层级读不出来 |
| Shadow 阴影 | 只用于说明浮起，不用于装饰 | 暗色主题弱化，靠描边与 tint | 暗色下漂浮的黑块 |
| Background Interaction 背景交互 | 下层内容滚动、播放时玻璃随之变化 | 下层真实渲染，玻璃透出即变 | 固定色值伪装成玻璃 |
| Dynamic Tint 动态着色 | 玻璃透出的色调来自真实下层内容 | 不固定 tint；需要主题色时用低饱和 `saturate` 而非叠色 | 全站一个“玻璃蓝” |
| Motion 动效 | 跟手 / 位置反馈符合平台习惯；reduced-motion 退化为静态磨砂 | transform + opacity，见 [motion](../visual-dna/motion.md) | 玻璃“瞬移”或过度回弹 |

受光方向全站一致：高光永远在同一侧。

## 3. 可复制要点

```css
/* 叠加在 .frosted 之上：高光 + 暗缘 + 一层真实阴影 */
.liquid-glass {
  box-shadow:
    inset 0 1px 0 rgb(255 255 255 / 0.35),
    inset 0 -1px 0 rgb(0 0 0 / 0.12),
    var(--ui-shadow-lg);
}
@media (prefers-reduced-motion: reduce) {
  .liquid-glass { transition: none; }   /* 退化为静态磨砂 */
}
```

## 4. 硬性约束

- 文字所在区域的背景必须可计算；玻璃底上的文字单列人工确认，不算自动通过。
- 每屏玻璃层克制（常驻浮层一层是常态）；玻璃层不承载密集正文。
- 大面积或滚动态 blur 有实测性能成本；低端设备提供实色降级。
- 用药剂量、金额、删除确认等高风险信息永远落在 [实色](solid.md) 面上。
- 系统原生材质（iOS / macOS）是平台现成能力，Web 实现是近似模拟，不宣称等同；原生感验收见 [native-review](../review/native-review.md)。

## 5. 快速判断

1. 这个面承载什么？高风险或密集正文 → 实色。
2. 它下面是什么？稳定底色 → [半透明](translucent.md)即可；动态媒体 → 至少磨砂。
3. 它是不是产品身份的一部分？不是 → 回到磨砂或实色。
4. 十一个维度里能做到几个？少于“材质 + 模糊 + 高光 / 暗缘 + 深度 + 动态 tint”这五项，就叫它磨砂，不叫液态玻璃。
