# Anti-generic：模板化信号逐条对照

用法：发现具体问题时按类别查阅，不作为每次交付的全量清单。每条给出症状 → 为什么是问题 → 替换方案。整体“像不像模板”的回看见 [anti-slop-review](../review/anti-slop-review.md)；排版类问题见 [typography](typography.md)；动效类见 [motion](motion.md)。

## 1. 默认脸

以下是缺少任务依据时的模板化信号，不是颜色或布局禁用清单。有明确依据的重复表格行、可比指标和媒体队列允许保留。

| 默认脸 | 为什么是问题 |
|---|---|
| 无任务依据的渐变主视觉 | 装饰抢占主信息 |
| 不经信息架构判断套用侧栏 + 顶栏 + 卡片 | 外壳比任务区更突出，没有业务优先级 |
| 三张等宽功能卡 | 内容并没有三块等分关系 |
| 满屏玻璃拟态 + 圆角 24px | 降低可读性，与“专业工具”气质相反 |
| 每个模块都是 icon + 标题 + 两行灰字 | 信息层级被压平，扫描效率低 |
| 主色用在 60% 面积上 | 颜色用完了，告警色没有对比空间 |
| 首屏四张统计卡数字是编的（99.99%、1,234,567） | 一眼假，且占位置 |

## 2. 布局

| # | 症状 | 为什么是问题 | 替换方案 |
|---|---|---|---|
| A1 | 无语义理由地嵌套重复容器 | 边界噪声压平主次 | 先内容、对齐与留白，再必要色调 / 规则线 |
| A2 | 三 / 四张完全等宽的功能卡整行铺开 | 内容不是等分关系 | 按内容权重给不同宽度；或改成列表 / 描述列表 |
| A3 | 所有区块都居中 | 阅读与操作路径不分主次 | 对齐跟随内容角色；密集任务保持稳定扫描轴 |
| A4 | 内容区限宽到 800px 居中 | 浪费大屏，表格被迫省略 | 业务页面用满宽度，长文用 42em 限宽 |
| A5 | 不经任务分析套用 Header + Cards | 外壳先于内容 | 按 [depth](depth.md) 选择构图与锚点 |
| A6 | 首屏塞满所有模块，没有主次 | 用户找不到该看哪里 | 一个页面一个主任务；次要信息下沉或折叠 |
| A7 | 表格默认 12 列全放出，横向滚动 | 看不到主键与操作列 | 默认列集 + 列设置；主键列固定 |

A2 的例外：KPI / 指标卡行等宽是合理的——可比性正是它要表达的。判定一句话：等宽是在强调可比性，还是在填充版面？

## 3. 视觉

| # | 症状 | 为什么是问题 | 替换方案 |
|---|---|---|---|
| B1 | 无任务依据的渐变主视觉 | 装饰代替焦点 | 锚点由任务、排版、数据或媒体产生 |
| B2 | 满屏玻璃拟态 / 毛玻璃 | 文字背景不可确定、性能成本高 | blur 默认关闭；真实浮层可选并提供可测承载面，见 [frosted](../materials/frosted.md) |
| B3 | 大标题用渐变文字 | 干扰阅读 | 实色 + 字重对比 |
| B4 | 无语义的发光边框 / 呼吸光圈 | 抢走内容注意力 | 告警先用文本与优先级；光效须有边界与降级 |
| B5 | 不校验的大面积极端明暗 | 长时间阅读不适或对比丢失 | 使用 Canvas / Surface 语义并实测 |
| B6 | 同角色圆角不一致、所有内容强塞圆角矩形 | 容器压过信息层级 | 按角色统一形状；允许有理由的例外 |
| B7 | 到处大阴影 + hover 上浮 8px | 业务系统不需要卡片漂浮 | 阴影只给真实浮层；hover 只改边框 / 底色 |
| B8 | 图标风格混用（线性 + 面性 + emoji） | 视觉噪声 | 一个项目一个图标家族，stroke-width 统一 |
| B9 | 主色铺满 60% 面积 | 告警色失去对比空间 | 主色只用于主操作与选中态 |

## 4. 内容与数据

| # | 症状 | 为什么是问题 | 替换方案 |
|---|---|---|---|
| E1 | 占位人名 `张三`、`李四`、客户名 `XX公司` | 一眼占位 | 真实感姓名与机构名，并标注为示例数据 |
| E2 | 编造漂亮数字后伪装业务事实 | 误导决策 | 标注模拟数据、来源与口径；换成不规则数字不等于真实 |
| E3 | 英文填充词 `Lorem ipsum`、`Elevate`、`Seamless` | 未完成信号 | 写真实中文文案 |
| E4 | 空态只有“暂无数据” | 用户不知道下一步 | 三段式空态，见 [typography](typography.md) §8 |
| E5 | 表格用 div 假表格、图表用假截图 | 不可用、不可访问 | 真表格 + 真实图表库 |
| E6 | 只有 loading，没有 error | 网络失败时用户懵 | loading / empty / error / denied 按需齐全 |
| E7 | 编号标记（01 / 02 / 03）用在非序列内容上 | 装饰而非信息 | 只有真的是步骤 / 序列才编号 |

## 5. 内容装饰（一眼 AI 的 production tells）

| # | 症状 | 替换方案 |
|---|---|---|
| F1 | 页面角落的版本号（`v0.6`、`BETA`、`Build 0048`） | 放“关于”里，主体界面不要 |
| F2 | 装饰性状态圆点（无真实语义） | 删除，或换成真实状态 |
| F3 | “滚动查看” / `↓ Scroll` 提示 | 删除 |
| F4 | 无意义的英文小标签（`BRAND. MOTION. SPATIAL.`） | 删除 |
| F5 | 区块标题右上角的漂浮说明文字 | 合并进标题或正文 |
| F6 | 装饰性十字 / 发丝网格线 | 删除 |
| F7 | 页头里的假产品截图 | 用真实可操作工作区，或去掉 |
| F8 | 图上叠 pill / badge 装饰 | 删除 |
| F9 | 天气 / 时区 / 城市条（产品不需要时） | 删除 |
| F10 | 长列表每行同时用上下双边框 | 只保留下边框 |
| F11 | 带填充底轨的进度装饰（非真实进度） | 删除，或改成真实进度条 |
| F12 | Emoji 当图标或进标题 | 用图标库或 SVG |

## 6. 工程 tells

| # | 症状 | 替换方案 |
|---|---|---|
| G1 | 交互元素只有默认态 | idle / hover / active / focus-visible / disabled |
| G2 | placeholder 当标签 | 标签常驻在输入框上方 |
| G3 | 硬编码颜色 / 尺寸 | 引用令牌 |
| G4 | `!important` 满屏 | `@layer` 与作用域收敛 |
| G5 | `z-index: 9999` | 使用 `--ui-z-*` 层级表 |
| G6 | 组件库替代产品决策 | 先确定构图再做语义映射；不强制改掉合理默认行为 |

## 7. 快速自查命令

```bash
# 命中数量应尽可能低（令牌文件除外）
grep -rEn "#[0-9a-fA-F]{3,8}" src --include=*.vue --include=*.scss | grep -v tokens
grep -rEn "z-index\s*:\s*[0-9]{3,}" src --include=*.vue
grep -rn "!important" src --include=*.vue | wc -l
grep -rn "outline:\s*none" src --include=*.vue
grep -rEn "letter-spacing:\s*-" src --include=*.vue
grep -rn "addEventListener('scroll'" src
grep -rn "Lorem\|张三\|李四\|XX公司\|Acme" src
grep -rn "😀\|🚀\|✨\|✅" src
```

较大改造时可运行 [scan-project.mjs](../assets/tools/scan-project.mjs) 做只读源码审计。

## 8. 不使用机械模板计数

不将“连续四次重复”写成无上下文禁令。表格、媒体队列和可比指标需要一致结构；真正要修的是没有主任务、所有区域等权、全灰底白卡和装饰边界过多。新建或调整布局后若仍模板化，改结构与信息分配，而不是只调整色值。
