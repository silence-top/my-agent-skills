# Depth：表面、空间节奏、尺度与构图

深度不是阴影的数量，而是“谁在谁之上、谁比谁重要”能否一眼读出。四个词汇：表面角色回答“内容浮在什么上”，节奏回答“谁和谁是一组”，尺度回答“谁先被看到”，构图回答“页面按什么关系组织”。材质（实色 / 半透明 / 磨砂 / 液态玻璃）见 [materials/](../materials/solid.md)。

## 1. 六种表面角色

表面是内容和交互的角色，不是六层必须嵌套的容器。默认顺序：内容 / 对齐 → 间距 → 色调 → 必要边界 → 真实浮层。只用 Canvas 和 Surface 也可以完成高质量列表。

| 角色 | 令牌 | 对比 | 描边 / 阴影 / 模糊 / 圆角 | 交互 |
|---|---|---|---|---|
| Canvas | `--ui-canvas`，页面承载层 | 为阅读区提供稳定底色 | 无描边、阴影、模糊；不设容器圆角 | 不响应无意义 hover |
| Surface | `--ui-surface`，主要工作 / 阅读区 | 与文字形成合格对比；不强制与 Canvas 强对比 | 优先间距分组；必要时单侧边界；不默认阴影 | 可编辑区保留焦点状态 |
| Elevated | `--ui-surface-elevated`，局部叠放 / 次级层 | 与下层可辨 | 必要边缘或低阴影；blur 默认关闭 | 选中与悬停不改变布局 |
| Floating | `--ui-surface-floating`，菜单、Dialog、Sheet | 与遮罩和文字都可辨 | 真实浮层使用阴影；blur 可选且需回退；形状取决于平台 | 焦点隔离、Escape、关闭恢复焦点 |
| Focus | `--ui-surface-focus`，当前任务 / 选中区域 | 品牌浅底 + 可读正文，不只靠色 | 焦点环或指示条；无须额外容器 | 键盘焦点与持久选中必须能区分 |
| Highlight | `--ui-surface-highlight`，极少量主操作 / 关键标识 | 对应 `--ui-text-on-highlight`；实测文字对比 | 不默认发光；避免整片正文涂品牌色 | 唯一主动作有按下、禁用与结果反馈 |

暗色不是“所有表面加描边”。可通过内容对比、色调和真实层级区分；阴影在深底不明显时才增加必要边缘。渐变、图片、半透明底上的文字若无法计算背景，按待人工确认处理，不算自动通过。

## 2. 五级空间节奏

| 角色 | 令牌 | 默认 | 用途 |
|---|---|---|---|
| Micro | `--ui-rhythm-micro` | 4px | 图标 / 标签内部关系 |
| Small | `--ui-rhythm-small` | 8px | 紧密相关控件与行内内容 |
| Medium | `--ui-rhythm-medium` | 16px | 一组内容的内部组织 |
| Large | `--ui-rhythm-large` | 32px | 不同任务或章节的分隔 |
| Hero | `--ui-rhythm-hero` | 64px | 媒体、专题、展示页的主要转折 |

这是一组关系，不是所有区块相同 padding。紧凑工作台可以不用 Hero；展示页也不能把所有组间距都设为 Hero。触控命中区与内容间距分别计算。页面内部优先采用 4/8/12/16/20/24/32/40/48/64px 刻度。

## 3. 六级视觉尺度

| 角色 | 令牌 | 默认 | 使用边界 |
|---|---|---|---|
| Micro | `--ui-scale-micro` | 12px | 非主要辅助标签，不能充当移动正文 |
| Small | `--ui-scale-small` | 13px | 桌面次级标注 |
| Base | `--ui-scale-base` | 16px | 可持续阅读正文与移动输入 |
| Large | `--ui-scale-large` | 24px | 区块或当前任务 |
| Hero | `--ui-scale-hero` | 38px | 页面主要对象或结论 |
| Display | `--ui-scale-display` | 48px | 有业务意义的展示标题，不是每页必选 |

## 4. 信息密度

桌面表格 compact / default / loose 为 36 / 44 / 52px 行高；移动 Compact / Balanced / Relaxed 区分必要摘要、主任务聚焦和阅读 / 媒体节奏，HTML 触控下限均为 48×48 CSS px。

密度不是把所有元素缩小。先删去非必要首屏信息或下钻，不能删关键风险和权限说明。形状按对象角色统一；无全局“三种圆角”配额。改变背景、边框或字号本身不能证明完成了视觉精修。

## 5. 构图选择树

先问用户主要在做什么：判断趋势 → Dashboard；持续处理对象 → Workspace；变换输入 → Tool；寻找对象 → Search-first；反复执行命令 → Command-oriented；消费内容 → Feed / Media-first / Editorial；检查单个对象 → Detail；提交资料 → Form-first；沉浸体验 → Immersive；扫描同类记录 → List-first。

Bento 只有当不同模块确有关联且面积需要表达权重时采用。页面不能因为有四个内容块就选择 Bento。

## 6. 构图目录

结构列同时定义从主到次的信息层级。每种构图是关系，不是固定组件树。

| 构图 | 适用 | 信息层级 | 主视觉焦点 | 桌面 | 移动 | 反例 |
|---|---|---|---|---|---|---|
| Dashboard | 发现异常与趋势 | 关键结论 → 主可视化 → 支持数据 → 可追溯明细 | 异常趋势或主要指标 | 主图占主要面积，支持指标成窄带 | 先结论和异常列表，图表按需展开 | 无可解释指标时不放 4 张同权 KPI 卡 |
| Workspace | 处理当前对象 | 待办队列 → 当前工作区 → 证据 / 上下文 → 辅助设置 | 正在处理的对象与证据关系 | 队列 / 主区 / 检查器，次区可收起 | 队列 → 详情 → 确认下钻 | 一次性表单不强行塞三栏 |
| Tool | 变换输入 | 输入 → 变换 → 结果 → 历史 / 说明 | 输入输出关系 | 分栏对照、可调整工作区 | 输入与结果分步，吸底执行 | 不用欢迎 Hero 把工作区挤到首屏外 |
| Feed | 内容流、动态 | 精选 → 紧凑条目 → 延伸内容 | 精选内容 | 主内容流 + 低权重侧区 | 精选后紧凑内容渐进加载 | 不是所有条目都用巨型卡片 |
| Editorial | 专题、报告 | 论点 → 主要证据 → 解释 → 补充资料 | 标题与关键证据的比例 | 阅读列 + 旁注，图表可通栏 | 先结论再证据，旁注就近折叠 | 高频管理操作不排成杂志长文 |
| Detail | 病历、报告、媒体详情 | 核心对象 → 关键属性 → 次级分区 → 相关动作 | 对象、标题或主要媒体 | 主属性与证据并置 | 核心摘要首屏；次信息下钻 | 不把每个字段包成卡片 |
| Media-first | 音乐、视频、影像 | 媒体 → 播放上下文 → 队列 → 元数据 | 内容本身 | 主媒体 + 队列 | 全幅内容、mini-player、拇指播放 | 没有媒体时明确空态，不用假封面 |
| Form-first | 资料录入、审批 | 当前步骤 → 必填字段 → 校验 → 提交 → 可选资料 | 当前步骤与完成进度 | 合理阅读宽度，辅助规则侧置 | 逐步披露，键盘可见，保留输入 | 不因整齐把逻辑无关字段排为两列 |
| Immersive | 播放、展览、专注 | 主要内容 → 最少上下文 → 关键动作 | 全幅内容或专注工作区 | 保留退出与关键状态 | edge-to-edge，安全区内操作 | 告警与关键状态不能被隐藏 |
| Bento | 有关联的能力 / 数据展示 | 主模块 → 互补模块 → 支持模块 | 语义权重最大的模块 | 不等面积网格表达优先级 | 重新选主模块，其他改为紧凑摘要 | 等面积卡墙不是 Bento |
| List-first | 后台清单、追溯 | 筛选上下文 → 记录 → 选中详情 → 批量操作 | 可扫描的关键列和状态 | 语义列宽、列可见性 | 主键 / 状态 / 下一步；其余进详情 | 不强制展示全部桌面列 |
| Search-first | 全局检索 | 查询 → 结果 → 解释 / 筛选 → 详情 | 查询与第一组匹配结果 | 筛选侧区与结果同行 | 搜索保持可达，筛选 Sheet，详情下钻 | 不用无结果的搜索框作装饰 |
| Command-oriented | 桌面工具、操作台 | 命令 → 参数 / 预览 → 执行结果 → 历史 | 命令入口和执行上下文 | 命令面板、焦点顺序、可发现快捷键 | 显式任务按钮替代快捷键依赖 | 不让用户猜命令，不覆盖输入法与浏览器保留键 |

```text
Dashboard                      Workspace                        Mobile Task
[关键结论         ][时间范围]   [队列 | 当前对象与证据 | 检查器]   [当前对象 + 流程位置]
[主要可视化                 ]   [     | 任务动作      |       ]   [必要信息与核对项   ]
[异常明细        |支持指标   ]                                    [次信息按需展开     ]
                                                                 [底部确认          ]
```

这些不是唯一布局。大小与顺序必须由业务优先级解释；不满足业务时更换构图，不能靠换颜色补救。

## 7. 桌面到移动的重构映射

- 桌面并列不意味着移动依次纵排。先决定保留、摘要化、下钻、延后四种处理，再写断点。
- 工作台的检查器在手机是详情上下文，不是页面末尾的附加卡片。
- 数据图表在手机可变成结论 + 可展开证据，保留数据表替代；不能删掉异常解释。
- 媒体可全幅，正文需要阅读宽度；统一 token 不要求统一 max-width。
- 重复列表行合理；重复无差别功能模块需要解释。一个大数字也不是所有 Dashboard 的默认锚点。

## 8. 验证

必须能指出主内容、入口动作、主锚点、低频信息去向。将主题切成灰度或另一主题后仍应能读出层级；只换肤不能改变信息层级。第二轮检查首屏是否被导航、介绍或四张卡片占满，而真实任务必须滚动才能到达。
