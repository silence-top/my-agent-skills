# Responsive Review：视口、缩放与溢出

配合 [visual-review](visual-review.md) 使用。响应式不是“缩小能看”，而是每个视口档位都有明确的结构决策；缩放与长文本是同一件事的另一面。

## 1. 视口矩阵

按本次变更选择受影响的档位，不要求每次全跑。

| 视口 | 结构决策 | 出处 |
|---|---|---|
| 1920×1080 | 增加工作区面积，不把控件无限拉宽；投屏可读 | [web](../platforms/web.md) / [electron](../platforms/electron.md) |
| 1440×900 | 主任务、队列、上下文并置 | |
| 1280×800 | 中后台设计基准 | [web](../platforms/web.md) §1 |
| 1024×768 | 必须可用：侧栏折叠为带可访问名称的图标轨道；检查器可收起，关键状态保留 | |
| 768×1024 | 过渡布局，明确合并或下钻的区域 | |
| 360×800、390×844、430×932 | 重新组织为移动任务，不是缩放画布 | [mobile](../platforms/mobile.md) |

## 2. 响应策略

- 设计基准 1280×800；1024 必须可用。< 1024 重新判断任务：低频属性进详情、编辑分步，只有真实比较表格允许在有标签的局部容器横向滚动。
- 折叠导航纯文字不能挤成 60–70px 竖排；必要时保留 ≥ 96px 的可读导航。
- 用 `min-width` 保住表格之前先考虑：隐藏低优先级列、把详情移到展开行。
- 移动端只做真正需要的场景（查询、审批、看状态），按 [mobile](../platforms/mobile.md) 的七种构图重组，不把 PC 页面缩小塞手机。
- 只读降级需要明确业务理由与提示。

## 3. 缩放与文字放大

- 浏览器缩放 200% 时布局不破、不出现页面级横向滚动条（业务系统可放宽到内容区局部横向滚动，导航必须可用）。
- 支持系统字号放大：至少 `html` 字号可被用户覆盖，不把所有字号写死到无法放大。
- 不用 `user-scalable=no` / `maximum-scale=1` 禁缩放。
- 行高与容器高度允许文字放大：避免 `height: 32px` + `line-height: 32px` 死锁，用 `min-height` + `padding`。
- 200% 缩放下控件可换行，工作区切换为分步结构。

## 4. 验收项

| # | 检查 | 判据 |
|---|---|---|
| 1 | 无溢出 | 受影响视口下页面整体无横向滚动；局部滚动容器有标签 |
| 2 | 1024 可用 | 侧栏折叠后仍有可访问名称；主任务可完成 |
| 3 | 移动重组 | 窄视口不是等比缩小；主动作、必要摘要保留 |
| 4 | 200% 缩放 | 布局不破、导航可用、操作不被遮 |
| 5 | 长文本 | 长中文、长数字、长英文单词换行或省略有策略，不撑破容器 |
| 6 | 真实测试 | 用实际 viewport 渲染验证，不把 CSS transform 缩放预览当作响应式测试 |
| 7 | 双主题 | 明暗主题在受影响视口各验一次 |

## 5. 边界

自动检查记录实际 viewport、主题、密度与完成状态；pending、缺测、超时不能绿色通过。缩短桌面视口只是软键盘布局压力测试，不等同于真机输入法验收，见 [mobile-review](mobile-review.md) §3。
