# Anti-Slop Review：这像不像 AI 生成的模板

新建或布局调整后做一次整体回看。逐项回答“是 / 否 / 不适用”，命中就改结构与信息分配，不是只换色。视觉判断不能由卡片计数、元数据标签或自动分数替代。

## 1. 十一问

- [ ] **视觉上是否泛化？** 去掉主色和强调色后，页面是否仍有清晰主次？换个业务名还能不能直接套用？
- [ ] **是否每个区块都是卡片？** “图标 + 标题 + 两行灰字”的等权卡片是否铺满；卡片里是否又套了卡片？
- [ ] **是否有不必要的圆角矩形？** 圆角、描边、底色是否在没有分组理由的地方出现？
- [ ] **玻璃是否被滥用？** 是否存在无任务依据的渐变、发光或玻璃层；玻璃上是否叠了玻璃；文字背景是否可计算？见 [materials/liquid-glass](../materials/liquid-glass.md) §5。
- [ ] **间距是否在制造层级？** 是分组间距 > 组内间距的节奏，还是只有等距堆叠？见 [depth](../visual-dna/depth.md) §2。
- [ ] **移动端是否被有意设计？** 是按任务重组（保留、摘要、下钻、延后），还是缩小的桌面？见 [platforms/mobile](../platforms/mobile.md)。
- [ ] **桌面端像真实应用程序吗？** 窗口、标题栏、右键、快捷键、拖放是否存在，还是窗口里的网站？见 [native-review](native-review.md)。
- [ ] **交互是否有意义？** 每个可点击元素是否有真实结果与状态反馈；hover / 动效是否解释了什么？
- [ ] **排版是否承担了层级？** 字号、字重、行长在做主次，还是全靠容器与分隔线？见 [typography](../visual-dna/typography.md)。
- [ ] **阴影是否被滥用？** 阴影是否只用于真实浮层；暗色主题下是否变成漂浮的黑块？
- [ ] **整体像不像 AI 模板？** 更像这个业务的工具，还是任何项目都能套用的样板？紫色渐变、发光按钮、三卡并列 Hero、居中大标题 + 副标题 + 两个按钮——命中几项？

## 2. 与 Avoid / Prefer 对照

| 命中的 Avoid | 转向的 Prefer |
|---|---|
| generic SaaS / generic dashboard | 主任务锚点先于外壳；按业务对象组织 |
| excessive cards | 空间层级：间距与对齐先于容器 |
| excessive gradients | 有意图的对比：一处强调，其余安静 |
| purple AI aesthetic | 从业务与品牌推导的克制配色 |
| random glassmorphism | 受控透明：材质有承载信息与空间关系的理由 |
| 等权堆叠 | 上下文表面：Canvas / Surface / Elevated 各司其职 |
| 装饰动效 | 克制动效：只解释状态、层级、反馈 |

完整对照表见 [premium-ui](../visual-dna/premium-ui.md) §1；逐条症状与替换方案见 [anti-generic](../visual-dna/anti-generic.md)。

## 3. 不使用机械模板计数

不把“连续四次重复”写成无上下文禁令。表格、媒体队列和可比指标需要一致结构；真正要修的是没有主任务、所有区域等权、全灰底白卡和装饰边界过多。新建或调整布局后若仍模板化，改结构与信息分配，而不是只调整色值。

## 4. 交付判断

按 [visual-review](visual-review.md) 检查本次影响的正确性与可用性，不另设一套重复清单。全局主题修改需覆盖实际支持的主题；局部修复无需重跑无关场景。无需 before / after 报告，不用人格命名或换色证明设计成立。
